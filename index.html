Why SupremeCSS

Everything a component needs, and nothing it doesn't.

The library is designed for teams that want consistent, polished interfaces without adopting a heavy framework or maintaining a large set of custom styles.

Copy-paste ready

Each component is delivered in three parts: semantic HTML, scoped CSS and optional JavaScript. Copy them into your project, or download a standalone file that already includes the base tokens.

Dark mode built in

Every colour, surface and border is read from a CSS custom property. Light and dark themes share one set of rules, so components stay consistent when the theme changes, without per-component overrides.

Light on runtime

Components are plain CSS and small, self-contained scripts with no framework dependency. Transitions are limited to purposeful feedback, and motion is disabled when the user has requested reduced motion.

Accessible defaults

Interactive controls are operable with the keyboard, focus states are clearly visible, and icon-only buttons carry descriptive labels. Overlays can be dismissed with the Escape key.

Documentation

Getting started

SupremeCSS components depend on a shared set of base tokens that define colour, typography, corner radius, spacing and motion. Add these tokens once per page, and every component will inherit the correct appearance automatically.

Step 1: Add the base tokens

Open any page in the Components gallery, select Copy base CSS in the top bar, and paste the result into a style element in the document head. The tokens are plain CSS custom properties, so they can be inspected and overridden in the browser developer tools.

<!doctype html>
<html lang="en" data-theme="light">
<head>
  <meta charset="utf-8">
  <style>
    /* paste "Copy base CSS" here */
  </style>
</head>
<body>
  …
</body>
</html>

Step 2: Add a component

Open a component and switch to the Code tab. The HTML, CSS and JavaScript are shown separately, so you can copy only the parts you need. Copy all places every part in one block, and Download saves a standalone HTML file that already contains the base tokens, so it works without a build step or an internet connection (aside from optional icon scripts).

Using components

Every component page follows the same structure, which makes it straightforward to move between them.

  • Preview renders the component live, in the current theme. Full screen mode gives you more room to test responsive behaviour.
  • Code exposes the HTML, CSS and JavaScript as separate tabs, each with its own copy action.
  • Interactive behaviour is written in small scripts that are scoped to the component, so several components can coexist on the same page without conflicts.
  • Icons are rendered with Lucide. Any component that uses icons requires the Lucide script, described in the Icons section below.

Theming and dark mode

The active theme is controlled by the data-theme attribute on the html element. Set it to "dark" or "light" to force a theme. Components never hard-code colours, so they update automatically when the attribute changes.

The theme toggle in the top bar stores the user's choice in localStorage under the key sc-theme. The inline script in the document head reads this value before the first paint, which prevents a flash of the wrong theme. When no choice has been saved, the page follows the operating system colour scheme.

Icons

Icons are provided by Lucide, pinned to version 0.469.0 so that the icon set does not change unexpectedly. Include the script once in the document, then call lucide.createIcons() after your markup is present. Each icon is written as an element with a data-lucide attribute that names the icon.

<script src="https://unpkg.com/lucide@0.469.0/dist/umd/lucide.min.js"></script>
<i data-lucide="check"></i>
<script>lucide.createIcons();</script>

Accessibility

Accessibility is treated as a baseline requirement rather than an optional enhancement. The following behaviours are built into the library.

  • Keyboard operation: Select, Command Palette and Search support the arrow keys for moving between options, Enter to confirm a choice and Escape to close the overlay.
  • Labels: icon-only buttons include an aria-label that describes their action, so screen reader users hear a meaningful name.
  • Focus: interactive elements display a visible focus ring when reached by the keyboard.
  • Motion: animations are reduced automatically when the operating system requests reduced motion.

Browser support

SupremeCSS targets current evergreen browsers. Several components use color-mix() to derive tints from the token palette, which requires a browser version released in 2023 or later. Older browsers will display the components with reduced colour variation but remain usable.

About SupremeCSS

A focused library built on restraint and precision.

SupremeCSS is a premium component library for developers and designers who need interfaces that feel finished without extensive setup. The library favours restraint: a monochrome palette, precise spacing, and motion that supports the interface rather than competing with it. Each component is designed to be read, understood and modified, so that it becomes part of your codebase rather than a dependency you cannot change.

Principles

How the library is built

Three principles guide every component, from its markup to its motion.

Restraint first

The default palette is monochrome, so colour is reserved for moments that need it, such as status, selection and destructive actions. This keeps interfaces calm and makes meaningful colour easy to notice.

Copy, then own it

Components are provided as readable source. You can change the markup, adjust the styles or extend the behaviour to suit your product, and the code remains yours to maintain.

Honest markup

Semantic elements, labelled controls and predictable keyboard paths come before visual refinement. A component should work correctly before it is made to look polished.
